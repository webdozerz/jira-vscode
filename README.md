# Jira для VS Code

Работа с задачами Jira Data Center (9.x) прямо из редактора: дерево задач, панель задачи, комментарии,
ворклоги, смена статуса и создание ветки под задачу. Авторизация — по персональному токену (PAT).

> Расширение рассчитано на Jira **Data Center / Server** (токен передаётся как `Bearer`).
> Jira Cloud (`*.atlassian.net`) использует другую схему авторизации и не поддерживается.

## Установка

Нужен VS Code 1.85+ и команда `code` в PATH (VS Code → `Shell Command: Install 'code' command in PATH`).
`code --install-extension` не понимает ссылок, поэтому файл сначала скачивается, затем устанавливается.

**macOS / Linux**

```bash
curl -fL -o /tmp/jira-vscode.vsix https://github.com/webdozerz/jira-vscode/releases/latest/download/jira-vscode.vsix \
  && code --install-extension /tmp/jira-vscode.vsix --force
```

**Windows (PowerShell)**

```powershell
Invoke-WebRequest https://github.com/webdozerz/jira-vscode/releases/latest/download/jira-vscode.vsix -OutFile $env:TEMP\jira-vscode.vsix
code --install-extension $env:TEMP\jira-vscode.vsix --force
```

Те же команды обновляют расширение до последней версии. После установки перезагрузите окно VS Code.

Без терминала: скачайте `jira-vscode.vsix` со страницы [Releases](https://github.com/webdozerz/jira-vscode/releases),
затем в VS Code **Extensions** → меню `…` → **Install from VSIX…**.

## Первый запуск

1. Откройте панель **Jira** в Activity Bar.
2. Создайте токен в Jira: **Профиль → Personal Access Tokens → Create token**.
3. Нажмите **Указать токен** и вставьте его. Токен проверяется запросом `/myself` и хранится в защищённом
   хранилище VS Code (SecretStorage), а не в `settings.json`.
4. Выберите проект (иконка в заголовке панели).

Адрес Jira задаётся настройкой `jira.baseUrl` (по умолчанию `https://jira.crypton.studio`).

## Что умеет

**Дерево задач**
- группировка по статусам или по спринтам; переключатель «мои / все»;
- фильтр по статусам (мультивыбор) и по спринту (активные, без спринта, конкретный);
- одна кнопка в заголовке панели сворачивает или разворачивает все группы (иконка меняется по состоянию);
- **Открыть задачу по ключу…** — вводите `SE-123` или вставляете ссылку (ключ из буфера обмена подставляется сам).

**Панель задачи** (клик по задаче)
- описание, комментарии и ворклоги в том виде, в каком их показывает Jira;
- родитель, эпик, подзадачи, связанные задачи (клик открывает их), вложения (открываются прямо в VS Code);
- спринты, исполнитель, затраченное и оставшееся время;
- **комментарий** с многострочным вводом, переключателем «Markdown → разметка Jira» и предпросмотром
  (его рисует сама Jira, так что видно ровно то, что получится);
- **ворклог**: время, дата начала и необязательный комментарий;
- **смена статуса** прямо в панели; после перехода сразу предлагаются следующие (`jira.chainTransitions`);
- **правка и удаление своих** комментариев и ворклогов;
- черновик комментария не теряется при обновлении панели.

**Ветка из задачи** (кнопка «Создать ветку» в панели, пункт контекстного меню задачи или команда)
- имя по шаблону, по умолчанию `feat/{key}` → `feat/SE-123`; перед созданием его можно поправить;
- работает через встроенное git-расширение VS Code; если ветка уже есть — предложит переключиться;
- после создания может перевести задачу в «In progress».

## Markdown в комментариях

Jira хранит текст в своей wiki-разметке, поэтому расширение конвертирует Markdown при отправке:

| Markdown | Jira |
|---|---|
| `# Заголовок` | `h1. Заголовок` |
| `**жирный**`, `*курсив*`, `~~зачёркнутый~~` | `*жирный*`, `_курсив_`, `-зачёркнутый-` |
| `` `код` `` и блоки ```` ```ts ```` | `{{код}}` и `{code:javascript}` |
| ссылки и картинки Markdown | `[текст\|url]`, `!url!` |
| списки, вложенные списки, `- [x]` | `*`, `**`, `#` |
| `> цитата`, таблицы, `---` | `bq.` / `{quote}`, `\|\|шапка\|\|`, `----` |
| `@логин` | `[~логин]` |

Если вы пишете сразу в разметке Jira — снимите галочку «Markdown → разметка Jira». При правке существующего
комментария конвертации нет: там уже разметка Jira.

## Настройки

| Настройка | По умолчанию | Описание |
|---|---|---|
| `jira.baseUrl` | `https://jira.crypton.studio` | Адрес Jira без завершающего `/` |
| `jira.maxIssues` | `200` | Сколько задач загружать в дерево |
| `jira.chainTransitions` | `true` | После смены статуса предлагать следующие переходы |
| `jira.markdownComments` | `true` | «Markdown → Jira» включён по умолчанию |
| `jira.branch.template` | `feat/{key}` | Шаблон ветки: `{key}` — SE-123, `{slug}` — название латиницей |
| `jira.branch.maxSlugLength` | `40` | Длина `{slug}` |
| `jira.branch.baseBranch` | _пусто_ | От какой ветки создавать (`develop`, `origin/develop`); пусто — от текущей |
| `jira.branch.moveToInProgress` | `ask` | `ask` / `always` / `never` — переводить ли задачу в работу после создания ветки |
| `jira.branch.inProgressStatus` | `In progress` | Название статуса «в работе» в вашем workflow |

## Если что-то не работает

| Сообщение | Что делать |
|---|---|
| «Токен недействителен или просрочен» | Создайте новый токен и укажите его заново |
| «Недостаточно прав для этого действия» | У вашей учётной записи нет права в проекте (комментировать, вести ворклог, менять статус) |
| «Не удалось связаться с Jira» | Проверьте VPN и `jira.baseUrl` |
| «Не найден git-репозиторий» | Откройте в VS Code папку проекта, в которой есть `.git` |
| Нет нужного статуса в списке | Показываются только переходы, доступные из текущего статуса по workflow проекта |

## Разработка

```bash
npm install
npm run watch        # пересборка при изменениях; F5 запускает Extension Development Host
npm test             # тесты (конвертер Markdown, имена веток, разбор спринтов, скрипт панели в jsdom)
npm run package      # проверка типов + тесты + сборка jira-vscode-<версия>.vsix
npm run icon         # перерисовать media/icon.png из media/icon.svg
```

**Выпуск версии:** поднять `version` в `package.json` и записать изменения в `CHANGELOG.md`, затем

```bash
npm run package
cp jira-vscode-<версия>.vsix /tmp/jira-vscode.vsix
gh release create v<версия> /tmp/jira-vscode.vsix --title v<версия> --notes-file <заметки>
```

Имя файла в релизе всегда `jira-vscode.vsix` — на него ссылается команда установки (`releases/latest/download/…`).

Используются методы Jira REST API: `/rest/api/2` (проекты, поиск, задача, комментарии, ворклоги, переходы,
поля), `/rest/agile/1.0` (доски и спринты), `/rest/api/1.0/render` (предпросмотр разметки).
